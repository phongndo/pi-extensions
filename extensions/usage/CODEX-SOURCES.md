# Codex usage and banked-reset contract

Checked against OpenAI's help center and the first-party `openai/codex` repository, commit `c53f342fecfb00a8d068024516f6483da8c852b4`.

- Banked resets are one-time promotional usage-limit resets, not purchased credits. Each offer has its own expiration; do not derive expiry from a fixed number of days. Applying one requires a user confirmation and can alter weekly reset dates. This extension is read-only. [OpenAI help](https://help.openai.com/en/articles/20001498-how-banked-codex-resets-work)
- The Codex client's passive ChatGPT usage reader issues `GET https://chatgpt.com/backend-api/wham/usage`. It does not send the optional Luna Reserve opt-in header. [Client implementation](https://github.com/openai/codex/blob/c53f342fecfb00a8d068024516f6483da8c852b4/codex-rs/backend-client/src/client/rate_limit_resets.rs)
- Reset details are fetched with `GET https://chatgpt.com/backend-api/wham/rate-limit-reset-credits`. Redemption is a separate POST `/consume`; the extension must never call it. [Implementation and exact endpoint tests](https://github.com/openai/codex/blob/c53f342fecfb00a8d068024516f6483da8c852b4/codex-rs/backend-client/src/client/rate_limit_resets_tests.rs)
- Reset response: `available_count`, `credits[]`. Each credit contains `id`, `reset_type`, `status`, `granted_at`, nullable `expires_at`, and optional `title`/`description`. Preserve missing expiry as unknown, not “never expires”. Show every returned entry, with its status; do not collapse credits into one expiry. [First-party types](https://github.com/openai/codex/blob/c53f342fecfb00a8d068024516f6483da8c852b4/codex-rs/backend-client/src/types.rs)
- Normal usage exposes `rate_limit`, optional `additional_rate_limits` and `credits`; additional limits carry `limit_name`, `metered_feature`, and `rate_limit`. [Usage schema](https://github.com/openai/codex/blob/c53f342fecfb00a8d068024516f6483da8c852b4/codex-rs/codex-backend-openapi-models/src/models/rate_limit_status_payload.rs), [additional limits](https://github.com/openai/codex/blob/c53f342fecfb00a8d068024516f6483da8c852b4/codex-rs/codex-backend-openapi-models/src/models/additional_rate_limit_details.rs)
- Each primary/secondary window reports `used_percent`, `limit_window_seconds`, `reset_after_seconds`, and Unix-seconds `reset_at`. [Window schema](https://github.com/openai/codex/blob/c53f342fecfb00a8d068024516f6483da8c852b4/codex-rs/codex-backend-openapi-models/src/models/rate_limit_window_snapshot.rs)
- The native client adds authorization plus `ChatGPT-Account-Id`. The extension restricts authorization to the exact official host and rejects redirects; neither credentials nor raw responses enter the local usage ledger. [Client headers](https://github.com/openai/codex/blob/c53f342fecfb00a8d068024516f6483da8c852b4/codex-rs/backend-client/src/client.rs)

These are first-party client endpoints, not a guaranteed stable public billing API. Authentication/availability/schema failures must display unavailable rather than zero resets or a fabricated balance. No live authenticated request was needed for this research.
