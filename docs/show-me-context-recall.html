Three pieces, now implemented

  1. Add recall in extensions/context/.

    One read-only tool named recall, with search and read-by-ID modes. It reads Pi’s saved branch history and returns short, traceable results, including before any number of resets.

    Read-only

  2. Add a small checkpoint.

    A separate notes tool saves goal, constraints, progress, failures, and next steps—with evidence IDs. Branch-local revisions survive reload, resume, fork, and tree navigation.

    Durable

  3. Reset at a verified safe boundary.

    Verify the persisted archive and latest steering coverage. After tools finish, open a fresh window and continue automatically. Missing/stale checkpoints use normal Pi compaction. Cross-model quality and cost still need evaluation.

    Default on

Three rules keep it simple

Local and branch-aware

Use pi’s session history. No private OpenAI backend, vector database, or cross-session memory in version one.

Retrieve a little at a time

Search returns snippets and IDs. Reads return bounded original content. Historical text stays evidence, not new instructions.

Keep a safe fallback

Normal pi compaction stays available. Never perform a summary-free reset merely because a checkpoint was supposed to be saved.
